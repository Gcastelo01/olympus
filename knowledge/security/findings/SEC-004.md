## Affected boundary and prerequisite

A local project contains a FIFO named as a valid Graveyard JSON record. Creation of a FIFO requires local filesystem access; Git does not normally transport FIFOs. No concurrent race is required. Registry readers, including optional Hermes hints, can encounter this path.

## Evidence

`src/graveyard.mjs:122` (`loadRecord`) resolves the contained path, then at line 134 opens with O_RDONLY/O_NOFOLLOW. It checks `handle.stat().isFile()` only afterward. A FIFO with no writer can block during open, so neither regular-file validation nor Git subprocess timeout is reached.

An authorized probe in a temporary Git repository called `inspectGraveyard(root, "GRAVE-001")` with such a special file. A supervising process terminated the child after three seconds: `fifo_process_exceeded_3s=true`. No application files were changed; the FIFO was removed after the probe. See [snapshot and hashes](../assessments/2026-10-20-hermes-hades-st05-t01/report.md).

## Impact and likelihood rationale

A local crafted registry entry can stall an otherwise read-only CLI and automated continuity preparation indefinitely. Blast radius is the caller's operation; no remote exploit, code execution or data exposure was demonstrated. MEDIUM/P2 reflects a concrete bounded-input contract failure with local prerequisites.

## Recommended remediation contract

SEC-004/T1: reject non-regular files before opening and retain descriptor validation after open. Use nonblocking/no-follow opening where supported so FIFO opening cannot stall even before descriptor checks. Keep byte limits and symlink rejection. Align with the existing bounded checkpoint reader where practical; no dependency or architectural redesign is required.

## Validation / acceptance gates

In a temporary Git repository, FIFO/no-writer, directory, symlink and oversized registry records must return promptly with explicit invalid/unavailable results across inspect/list/validate/exhume and Hermes hints; no export or application writes. A normal regular record remains valid. Supervise the FIFO test to prevent a stuck suite and mark platforms without FIFO support explicitly. Retain post-open regular-file and bounded-read checks. Aegis repeats the independent FIFO probe after correction; Argus reviews the final implementation.
