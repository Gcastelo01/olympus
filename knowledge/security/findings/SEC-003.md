# SEC-003 — Missing promisor objects can invoke configured fetch processes

- Assessment: 2026-10-20-graveyard-st03-t01; scope: ST03-T01 Git observation boundary; revision: `8b881663e24261339728696816d4ffeaeec52a2d`, `feat/hermes-hades`, dirty working-tree snapshot

- Lifecycle: VERIFIED_FIXED
- Severity: HIGH
- Priority: P1; Confidence: HIGH (configured process execution observed locally)
- References: [CWE-829, CWE 4.20](https://cwe.mitre.org/data/definitions/829.html); [Git no-lazy-fetch documentation](https://git-scm.com/docs/git), verified 2026-10-20.

## Affected boundary and prerequisite

A project is configured as a promisor/partial repository and a referenced historical object is unavailable locally. Repository-local remote configuration controls fetching. This configuration requires local metadata control; a tracked Graveyard record by itself does not provide it. The accepted architecture explicitly prohibits automatic fetching or executing configured programs during observation.

## Evidence

At the assessed hash, `src/graveyard.mjs:78` restricts environment and disables fsmonitor, but does not disable lazy fetching. `retrieveFiles` passes the validated historical blob ID to `cat-file`; Git may fetch missing promisor objects before returning.

The authorized local probe used a temporary retirement repository, a local-only promisor remote, and a benign configured upload helper that only created a marker in that temporary directory. Removing the fixture's original loose blob caused `exhumeGraveyard` to report `Git history/object unavailable`, while the marker proved that the configured helper had run. Result: `configuredFetchHelperExecuted=true`. No real remote, network probe or sensitive data was used. Probe: `/tmp/aegis-st03-promisor.mjs`, not shipped.

The generic exception masks the output but does not prevent the subprocess side effect.

## Impact and likelihood rationale

A purported observation can execute repository-configured code with the caller's OS permissions, initiate unrequested network access, or write fetched objects. A malicious preconfigured repository is required; this is not a claim that a normal clone imports executable local configuration. Command execution across the stated untrusted-repository boundary warrants HIGH/P1. No production compromise was observed.

## Recommended remediation contract

Disable lazy fetch and prohibit implicit transport/process access for all observation subprocesses, including history discovery and blob reads. Use controls actually supported by the project's Git floor; current Git documents `GIT_NO_LAZY_FETCH=1` / `--no-lazy-fetch`. Fail closed on unsupported runtimes or unavailable objects. A version-incompatible environment variable must not silently provide a false guarantee. Do not change repository config or perform a fetch to make verification pass.

## Validation / acceptance gates

Use isolated local promisor fixtures with absent blob and tree/history objects. Configure a benign process marker. All applicable commands must return unavailable/error with no marker, no fetch/object-store additions, no application changes, and no secret echo. Cover both inspection/export paths, supported Git version behavior, existing environment/fsmonitor checks and ordinary local-history success. Aegis reassesses this exact abuse path after repair.
