# SEC-002 — Git replacement objects break Graveyard blob provenance

- Assessment: 2026-10-20-graveyard-st03-t01; scope: ST03-T01 historical object reads; revision: `8b881663e24261339728696816d4ffeaeec52a2d`, `feat/hermes-hades`, dirty working-tree snapshot

- Lifecycle: VERIFIED_FIXED
- Severity: MEDIUM
- Priority: P2; Confidence: HIGH (isolated reproduction)
- References: [CWE-354, CWE 4.20](https://cwe.mitre.org/data/definitions/354.html); [Git replace documentation](https://git-scm.com/docs/git-replace), verified 2026-10-20.

## Affected boundary and prerequisite

An existing local Git replacement ref can change the object returned by a nominal object ID. This requires control of local Git metadata or an intentionally configured replacement; an ordinary tracked file alone cannot install that ref. Graveyard promises recovery of descriptor-identified historical bytes.

## Evidence

At the assessed hash, `src/graveyard.mjs:78` (Git wrapper) does not disable replacement objects. `treeBlob` compares tree IDs with record descriptors, while `retrieveFiles` calls `cat-file blob <beforeBlob>` and labels returned bytes with that descriptor ID.

An authorized isolated temporary repository contained a normal two-commit retirement and a different synthetic blob. A local replacement ref mapped the original blob to the second. `exhumeGraveyard` returned:

- trace: BURIED
- advertised blob equals original descriptor: true
- returned bytes equal original content: false
- returned bytes equal replacement content: true

No application restoration, real credential or network access occurred. The local reproduction script was `/tmp/aegis-st03-replace.mjs`; it is not a shipped artifact. Git explicitly documents replacement refs applying by default, including to `cat-file`.

## Impact and likelihood rationale

An operator or future agent receives false provenance for recovered implementation content. Actual application reintegration still requires normal review, which limits impact. This is a concrete integrity error, not proof of remote execution or an observed incident.

## Recommended remediation contract

Read the actual Git objects and graph consistently, ignoring local replacement overlays for every Graveyard Git subprocess. Git's `--no-replace-objects` global option is a narrow implementation option. Do not delete or modify user replacement refs. Keep unsupported/missing object histories unavailable, without fabricating provenance.

## Validation / acceptance gates

In temporary repositories, install blob and commit replacement refs. Validate/inspect/exhume must use real objects and history or fail clearly; they must never advertise an original object while emitting replacement bytes. Check both JSON inspection and export receipts. Preserve replacement refs and application files. Rerun existing rewritten-history fixtures and obtain Aegis reassessment.
