# SEC-001 — Recognizable credentials pass the checkpoint filter

- Assessment: 2026-10-20-hermes-st02-t02; scope: Hermes input, persistence and output; revision: dirty snapshot based on `41e7a42ea8aa72fb1f6e3fd830c82168087ab0d0`.
- Evidence status: CONFIRMED
- Lifecycle: VERIFIED_FIXED (2026-10-20-hermes-st02-t02-02; exact hashes recorded in reassessment)
- Severity: MEDIUM
- Priority: P1; Confidence: HIGH — parser and complete save/inspect/load paths reproduced with synthetic data.
- References: [MITRE CWE-312, version 4.20](https://cwe.mitre.org/data/definitions/312.html); [official GitHub token formats](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github#githubs-token-formats), verified 2026-10-20. Contract: `knowledge/architecture/hermes-hades.md`, Security, failures and resource bounds.

## Affected boundary and prerequisite

A user or producing agent supplies free text that accidentally includes a recognizable credential, or imports a checkpoint containing one. Credentials are prohibited checkpoint data. The CLI is local; no unauthenticated remote entry point was found. A later harness may receive the returned context. The user must first supply the sensitive text; Hermes does not collect these tokens from an external account.

## Evidence at original assessment

`src/state-primitives.mjs:8` recognizes a GitHub-like prefix followed by a hyphen, whereas GitHub's documented token family uses an underscore. Fine-grained token prefixes and explicit Authorization Bearer annotations are also absent from the recognizers. The recursive string scan reuses this same expression.

Source-to-sink path: `saveContext` → `parseBoundedJson` / `assertNoSensitiveContent` → validated objective → JSON serialization → `writeExclusive`. `inspectContext` and `loadContext` parse the stored document with the same filter and return its objective; `bin/olympus.mjs:75` serializes the result to stdout.

On 2026-10-20 an isolated temporary Git fixture supplied three synthetic text samples representing classic GitHub, fine-grained GitHub and explicit bearer credentials. Each yielded `persisted=true`, `inspectEcho=true`, `loadStatus=READY`, `loadEcho=true`. The fixture was removed afterward. No real token was read, printed or used. A synthetic `api_key=` control was rejected. Complete token-shaped samples and executable payloads are intentionally omitted from this report.

## Impact and likelihood rationale

Recognizable credentials can be stored in cleartext and reintroduced into context output, where handoff to a different provider expands exposure. Mode 0600, local execution, explicit user selection and the existing warning reduce exposure; they do not implement the promised recognizable-secret rejection. No actual leak, account compromise or network transfer was observed. MEDIUM reflects the required user/agent mistake and limited local surface. P1 prioritizes a small corrective change before this feature is delivered.

## Recommended remediation contract

Correct the documented token-prefix separators and cover recognizable fine-grained GitHub credentials and explicit bearer authorization values in the shared scanner. Keep the scanner deterministic, dependency free and fail closed without echoing the rejected value. Apply the same checks to decoded nested string values and referenced artifacts. Retain the truthful limitation that arbitrary prose cannot be proved secret free; do not add network validation or encryption infrastructure.

## Validation / acceptance gates

Use only synthetic fixtures. Reject known credential families in objective/nextStep/memory strings, JSON escape variants and referenced artifact content before a new checkpoint is created. Reject hand-crafted stored checkpoints at inspect/load/discover. Cover existing private-key and named-secret detection, harmless mentions of provider/token family names without values, and valid normal saves. Assert stdout/stderr errors do not contain synthetic values. Run relevant context/primitives tests; hand off actual hashes to Argus and request Aegis reassessment.
